# CampusHub Phase 4 演示说明

本文档对应 Phase 4 交付物 9，用于说明 CampusHub 可演示版本的运行方式、演示账号或测试数据，以及核心演示路径。

## 一、演示环境

| 项目 | 说明 |
|------|------|
| 后端 | Spring Boot 3.3.5，JDK 17，默认端口 `8080` |
| 前端 | Vue 3 + Vite，开发环境默认端口 `5173` |
| 数据库 | MySQL 8.0，数据库名 `campushub_db` |
| 缓存 | Redis 7 |
| 推荐浏览器 | Chrome / Edge |

## 二、运行方式

### 2.1 本地开发方式

1. 在项目根目录启动基础设施：

```bash
docker-compose up -d
```

2. 启动后端。

当前 `docker-compose.yml` 将 MySQL 暴露到宿主机 `3307` 端口，Redis 暴露到 `6379` 端口；因此本地直接运行后端时建议显式覆盖连接参数：

```bash
cd backend
mvn spring-boot:run -Dspring-boot.run.arguments="--spring.datasource.url=jdbc:mysql://localhost:3307/campushub_db?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true --spring.datasource.username=ch_dev --spring.datasource.password=ch_password --spring.data.redis.host=localhost --spring.data.redis.port=6379"
```

3. 启动前端：

```bash
cd frontend
npm install
npm run dev
```

4. 访问系统：

```text
前端页面：http://localhost:5173/
后端健康检查：http://localhost:8080/api/v1/health
```

### 2.2 Docker 生产演示方式

如需使用完整 Docker Compose 方式演示，可在项目根目录执行：

```bash
export CAMPUSHUB_JWT_SECRET="$(openssl rand -base64 32)"
bash deploy.sh
```

启动后访问：

```text
http://localhost/
```

生产演示方式中，前端由 Nginx 提供静态资源，`/api/*` 请求通过 Nginx 反向代理到后端容器。

## 三、演示账号与测试数据

### 3.1 推荐演示账号

为了保证登录密码经过 BCrypt 正确加密，推荐在演示前通过注册页面创建以下账号：

| 角色 | 用户名 | 密码 | 用途 |
|------|--------|------|------|
| 发布者 | `demo_pub` | `pass123456` | 发布需求、确认完成、评价接单者 |
| 接单者 | `demo_rec` | `pass123456` | 浏览需求、接单、提交验收、评价发布者 |

创建方式：

1. 打开 `http://localhost:5173/register`
2. 分别注册 `demo_pub` 和 `demo_rec`
3. 注册成功后回到登录页登录对应账号

### 3.2 初始化演示数据

首次启动 MySQL 容器时，`mysql-init/init.sql` 会初始化基础表和部分演示数据：

| 数据表 | 示例数据 |
|--------|----------|
| `sys_user` | `test_user1` 普通用户、`test_admin` 管理员 |
| `biz_requirement` | 快递代拿、资料互换、二手显示器等需求 |
| `biz_notification` | 个人资料同步、需求状态提醒、系统提示 |

注意：初始化脚本中的 `test_user1`、`test_admin` 的 `password_hash` 为占位值，主要用于数据库展示和接口联调。如果要直接登录这两个初始化账号，需要先将密码更新为 BCrypt 哈希，或通过注册页面创建新的演示账号。

如需演示管理后台，可执行以下 SQL 将 `test_admin` 密码设置为 `pass123456`：

```bash
docker exec campushub-mysql mysql -u ch_dev -pch_password campushub_db -e 'UPDATE sys_user SET password_hash="$2y$10$jb97oCVlvfcHKe9rjrswwuG35Md5TF3ZG941SL5.84uj6OHXzgkw6" WHERE username="test_admin";'
```

之后可使用：

| 角色 | 用户名 | 密码 | 用途 |
|------|--------|------|------|
| 管理员 | `test_admin` | `pass123456` | 进入管理后台，下架需求，查看用户、需求、订单 |

## 四、核心演示路径

### 路径 1：用户注册与登录

1. 打开 `http://localhost:5173/`
2. 未登录状态会跳转到 `/login`
3. 点击“去注册”，注册 `demo_pub`
4. 返回登录页，输入 `demo_pub / pass123456`
5. 登录成功后进入首页或需求大厅，侧边栏展示需求大厅、发布需求、我的订单、个人资料、消息通知等入口

验收点：
- 注册成功后数据库中新增用户
- 登录成功后前端保存 JWT
- 未登录访问受保护页面会被路由守卫拦截

### 路径 2：发布需求与需求大厅筛选

1. 使用 `demo_pub` 登录
2. 进入“发布需求”
3. 填写标题、描述、预算和分类，例如：
   - 标题：`演示用快递代拿`
   - 描述：`菜鸟驿站取件，送到宿舍楼下`
   - 预算：`8`
   - 分类：`快递跑腿`
4. 提交后进入“需求大厅”
5. 使用关键字或分类筛选刚发布的需求
6. 点击需求卡片进入详情页

验收点：
- 已登录用户可以发布需求
- 必填校验和预算校验生效
- 列表分页、分类、关键字筛选可用
- 详情页展示标题、描述、预算、发布者和状态

### 路径 3：接单与订单流转

1. 退出 `demo_pub`
2. 使用 `demo_rec / pass123456` 登录
3. 进入“需求大厅”，打开 `demo_pub` 刚发布的需求
4. 点击“接单”
5. 进入“我的订单”，在“我接取的”中查看该订单
6. 打开订单详情，点击“提交验收”，订单进入 `TO_CONFIRM`
7. 退出 `demo_rec`，重新登录 `demo_pub`
8. 进入“我的订单”中的“我发布的”，打开对应订单
9. 点击“确认完成”，订单进入 `COMPLETED`

验收点：
- 发布者不能接自己的需求
- 同一需求只能被接单一次
- 订单状态按 `IN_PROGRESS -> TO_CONFIRM -> COMPLETED` 流转
- 非订单参与者无法查看他人订单详情

### 路径 4：订单评价与信用分

1. 在 `demo_pub` 登录状态下，打开已完成订单详情
2. 选择星级并填写评价内容，提交评价
3. 退出后使用 `demo_rec` 登录
4. 打开同一订单详情，提交对发布者的评价
5. 进入“个人资料”查看信用分变化

验收点：
- 只有已完成订单可以评价
- 双方各可评价一次
- 评分限制在 1-5 星
- 评价会影响被评价方信用分

### 路径 5：消息通知

1. 登录任意演示账号
2. 进入“消息通知”
3. 查看通知列表和未读数量
4. 点击已读或批量已读操作

验收点：
- 用户只能查看自己的通知
- 未读数量能正确展示
- 已读状态更新后页面同步变化

### 路径 6：管理后台

1. 使用 `test_admin / pass123456` 登录
2. 进入侧边栏“管理后台”
3. 查看用户、需求、订单列表
4. 对某条待处理需求点击“下架”
5. 重新进入需求大厅，确认该需求不再作为可接单需求展示

验收点：
- 管理员可进入后台
- 普通用户调用管理接口会返回无权限
- 管理员可下架违规或过期需求

## 五、接口演示补充

如需用命令行快速验证后端：

```bash
# 健康检查
curl http://localhost:8080/api/v1/health

# 注册普通用户
curl -X POST http://localhost:8080/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"demo_api","password":"pass123456","campus":"仙林校区"}'

# 登录获取 token
curl -X POST http://localhost:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"demo_api","password":"pass123456"}'
```

登录成功后，从响应中复制 `token`，后续访问受保护接口时添加：

```text
Authorization: Bearer <token>
```
