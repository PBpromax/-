## 五、发现并修复的 Bug

### Bug #1: ApiCode 错误码 4003 语义冲突（未修复，已记录）

`ApiCode.USERNAME_TAKEN(4003)` 与 `EvaluationServiceImpl` 中硬编码的 `BusinessException(4003, "订单尚未完成")` 冲突。

**影响：** 前端无法区分"用户名已存在"和"订单未完成"两种错误。

**建议修复：** 在 `ApiCode` 中新增 `ORDER_NOT_COMPLETED` 等评价专属错误码。

### Bug #2: 通知 ID 毫秒级时间戳碰撞（✅ 已修复）

`NotificationService.createNotification()` 使用 `LocalDateTime.now().toEpochMilli()` 作为主键，同一毫秒内创建多条通知时 `DuplicateKeyException`。

**修复：** 改用 `AtomicLong.incrementAndGet()`，初始值 = `System.currentTimeMillis()`。

**验证：** 修复前 6 个测试因主键冲突失败，修复后全部 79 个测试通过。

### Bug #3: EvaluationServiceImpl 测试覆盖不足（✅ 已修复）

原有测试仅 3 个用例，缺少 4/3/2 星信用分计算和非参与者、重复评价异常路径。

**修复：** 扩展至 10 个测试用例，覆盖全部星级和所有异常路径。

## 六、遇到的问题与解决

| 问题 | 解决方式 |
|------|----------|
| MyBatis-Plus 3.5.9 `BaseMapper` 新增 `insert(Collection<T>)` 等重载方法，导致 Mockito `verify().insert(any())` 编译歧义 | 使用 `ArgumentMatchers.<SysUser>any()` 显式类型见证，并添加 `import org.mockito.ArgumentMatchers;` |
| `RedisConfig` 在测试环境尝试创建 `RedisTemplate` 但因无 Redis 连接失败 | 添加 `@Profile("!test")` 使测试环境跳过 Redis 配置 |
| H2 不支持 MySQL 的 `ON UPDATE CURRENT_TIMESTAMP` | 项目使用 MyBatis-Plus `@FieldFill` 自动填充，不依赖数据库层，无需额外处理 |
| 中文智能引号（Unicode `“` `”`）导致 javac 编译失败 | 替换为 ASCII 引号 |
| H2 中 `CURRENT_TIMESTAMP` 对同批插入的多行记录可能返回相同值，导致 `ORDER BY created_at` 不确定 | 修改断言为内容匹配而非顺序匹配 |
| EvaluatonServiceImpl 校验顺序：先检查订单状态(4003)再检查参与者(4004)，非参与者+未完成订单返回 4003 而非 4004 | 集成测试调整为覆盖两种场景：未完成→4003，已完成+非参与者→4004 |
