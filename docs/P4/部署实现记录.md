## 一、部署目标

将 CampusHub 项目部署到阿里云 ECS 服务器（2 vCPU / 4 GiB，公网 IP `101.132.23.129`），通过 Docker Compose 统一编排所有服务，实现**一键部署**。用户可直接通过公网 IP 访问完整系统。

## 二、部署架构

```
用户浏览器
    │  http://101.132.23.129:80
    ▼
┌──────────────────────────────────────────┐
│  Nginx 容器 (:80)                         │
│  ├─ 静态文件: /usr/share/nginx/html       │
│  ├─ /api/* → backend:8080 (反向代理)      │
│  └─ SPA 回退: try_files $uri /index.html  │
└──────────────────────────────────────────┘
    │ campushub-net (Docker 内部网桥)
    ▼
┌──────────────────────────────────────────┐
│  Backend 容器 (Spring Boot :8080)         │
│  ├─ profile: prod                         │
│  ├─ JVM: -Xms256m -Xmx1024m               │
│  └─ 访问 campushub-db:3306 / campushub-redis:6379 │
└──────────────────────────────────────────┘
    │                    │
    ▼                    ▼
┌──────────┐    ┌──────────┐
│  MySQL   │    │  Redis   │
│  8.0     │    │  7.0     │
│  (内网)  │    │  (内网)  │
└──────────┘    └──────────┘
```

**安全设计**: 仅 Nginx 的 80 端口对外暴露，MySQL(3306)、Redis(6379)、Backend(8080) 均仅 Docker 内网可访问。

## 三、服务器环境准备（完整操作流程）

以下所有命令在服务器上以 `root` 用户执行。

### 3.1 安装 Docker

```bash
# 更新 yum（阿里云 CentOS / Anolis 默认包管理器）
sudo yum update -y

# 安装 Docker
sudo yum install -y docker

# 启动 Docker
sudo systemctl start docker

# 设置开机自启
sudo systemctl enable docker

# 验证安装（预期：24.x 及以上）
docker --version
```

### 3.2 安装 Docker Compose v2

```bash
# 下载 Docker Compose 插件
# 注意：不要用 $(uname -s) 变量展开，某些终端会截断 URL，直接写死 linux-x86_64
sudo curl -L "https://get.daocloud.io/docker/compose/releases/download/v2.27.0/docker-compose-linux-x86_64" \
  -o /usr/libexec/docker/cli-plugins/docker-compose

# 添加执行权限
sudo chmod +x /usr/libexec/docker/cli-plugins/docker-compose

# 验证安装（预期：v2.27.0 及以上）
docker compose version
```

### 3.3 给当前用户添加 Docker 权限

```bash
sudo usermod -aG docker $USER

# 退出 SSH 重新登录，或执行以下命令立即生效
newgrp docker
```

### 3.4 安全组开放 80 端口（阿里云控制台操作）

**说明**：阿里云安全组是 ECS 实例的虚拟防火墙，默认只开放 22 端口（SSH），需要手动添加 80 端口的入站规则。

**操作步骤**：

1. 登录 [阿里云控制台](https://ecs.console.aliyun.com)，进入「实例与镜像」→「实例」
2. 找到 ECS 实例 `iZuf61rhx76bw4bvqv2f7qZ`（IP: `101.132.23.129`），点击实例名称进入详情
3. 点击「安全组」标签，再点击安全组 ID（格式类似 `sg-xxxxx`）
4. 在「入方向」标签页，点击「手动添加」，填写：

| 配置项 | 填写内容 | 说明 |
|--------|----------|------|
| 授权策略 | **允许** | |
| 优先级 | **1** | 数字越小优先级越高 |
| 协议类型 | **自定义 TCP** | |
| 端口范围 | **80/80** | 仅开放 HTTP 端口 |
| 授权对象 | **0.0.0.0/0** | 允许所有公网 IP 访问 |
| 描述 | CampusHub 前端访问 | 备注用途 |

5. 点击「保存」

**确认结果** — 入方向规则应包含以下两条：

| 优先级 | 协议类型 | 端口范围 | 授权对象 | 描述 |
|--------|----------|----------|----------|------|
| 1 | 自定义 TCP | 80/80 | 0.0.0.0/0 | CampusHub 前端访问 |
| 110 | 自定义 TCP | 22/22 | 0.0.0.0/0 | SSH 远程连接（默认） |

> **安全提醒**：绝对不要开放 3306（MySQL）、6379（Redis）、8080（Spring Boot）端口到公网。这些服务只通过 Docker 内部网络访问。

## 四、新增文件详解

### 1. `backend/src/main/resources/application-prod.yml` — 生产环境配置

**功能**: 覆盖开发环境配置，适配 Docker 容器化部署。

| 配置项 | 值 | 说明 |
|--------|-----|------|
| 数据库地址 | `campushub-db:3306` | 通过 Docker 服务名访问，不依赖固定 IP |
| Redis 地址 | `campushub-redis:6379` | 通过 Docker 服务名访问 |
| SQL 日志 | `NoLoggingImpl` | 生产环境关闭 SQL 输出，减少日志量 |
| 日志级别 | `com.campushub: INFO`, `root: WARN` | 只记录关键业务日志 |
| 日志文件路径 | `/app/logs` | 容器内持久化日志目录 |
| JWT Secret | 从环境变量 `CAMPUSHUB_JWT_SECRET` 读取 | 避免密钥硬编码，有默认值兜底 |

### 2. `backend/Dockerfile` — 后端镜像构建

**功能**: 多阶段构建，分离编译环境和运行环境，减小镜像体积。

| 阶段 | 基础镜像 | 操作 |
|------|----------|------|
| 构建阶段 | `maven:3.9-eclipse-temurin-17` | 复制 pom.xml + 源码 → `mvn package -DskipTests` |
| 运行阶段 | `eclipse-temurin:17-jre` | 只复制 JAR 包，JVM 参数 `-Xms256m -Xmx1024m` |

**关键细节**:
- 第一阶段使用阿里云 Maven 镜像加速依赖下载
- `mvn dependency:go-offline` 在 COPY 源码前执行，利用 Docker 缓存层避免重复下载依赖
- 运行阶段使用 JRE 而非 JDK，镜像更轻量
- JVM 内存限制 1GB，为 MySQL/Redis 预留足够内存

### 3. `frontend/Dockerfile` — 前端镜像构建

**功能**: 多阶段构建，Node 编译 Vue 项目 → Nginx 托管静态文件。

| 阶段 | 基础镜像 | 操作 |
|------|----------|------|
| 构建阶段 | `node:20-alpine` | `npm ci` → `npm run build`（Vite 打包） |
| 运行阶段 | `nginx:1.27-alpine` | 复制 `dist/` 到 `/usr/share/nginx/html`，替换 nginx.conf |

### 4. `frontend/.env.production` — 前端生产环境变量

**功能**: 设置生产构建时的 API 请求基地址。

```
VITE_API_BASE_URL=/api
```

前端所有 API 请求使用**相对路径 `/api`**，由 Nginx 反向代理到后端。无需硬编码服务器 IP，部署到任何服务器都能正常工作。

### 5. `frontend/nginx.conf` — Nginx 配置

**功能**: 前端静态文件托管 + API 反向代理 + SPA 路由支持。

| 配置块 | 功能 | 关键指令 |
|--------|------|----------|
| `location /api/` | API 反向代理 | `proxy_pass http://backend:8080` + 保留原始 Host/IP 头 |
| `location /` | 前端静态文件 | `try_files $uri $uri/ /index.html`（SPA history 模式回退） |
| `gzip` | 压缩优化 | 对 CSS/JS/JSON/HTML/SVG 启用 gzip，最小 256 字节 |

**SPA 回退原理**: Vue Router 使用 HTML5 History 模式，用户直接访问 `/requirements` 等路径时，Nginx 不认识这个路径，需要回退到 `index.html` 让前端路由接管。

### 6. `docker-compose-prod.yml` — 生产环境服务编排

**功能**: 一键启动 4 个服务，定义网络和卷。

| 服务 | 端口暴露 | 数据卷 | 依赖 |
|------|----------|--------|------|
| `campushub-db` (MySQL 8.0) | 无（仅内网） | `mysql-data:/var/lib/mysql` + `./mysql-init` 初始化脚本 | — |
| `campushub-redis` (Redis 7.0) | 无（仅内网） | `redis-data:/data` | — |
| `backend` (Spring Boot) | 无（仅内网） | — | db, redis |
| `nginx` (Nginx) | **80:80** | — | backend |

**关键设计**:
- MySQL/Redis 使用具名卷持久化，容器重启数据不丢失
- 所有服务加入同一 Docker 网桥 `campushub-net`，通过服务名互相访问
- 敏感信息（数据库密码、JWT Secret）通过 `${VAR_NAME}` 语法从宿主机环境变量注入
- 仅 Nginx 80 端口映射到宿主机

### 7. `deploy.sh` — 一键部署脚本

**功能**: 自动化完整部署流程。

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | `git pull origin develop` | 拉取最新代码 |
| 2 | `docker compose build` | 构建后端 + 前端镜像 |
| 3 | `docker compose up -d` | 后台启动所有服务 |
| 4 | 健康检查 | `curl /api/v1/health` + `curl /` 验证 |

含错误处理（`set -e`）、环境变量自动生成、部署后常用命令提示。

## 五、修改文件详解

### 1. `backend/.../config/CorsConfig.java`

**修改前**: 仅允许 `localhost:5173`
**修改后**: 新增 `http://localhost`、`http://101.132.23.129`

**说明**: 在生产环境中，前后端通过 Nginx 同源代理，CORS 实际上不会触发。添加这些来源是为了兼容开发和服务器端直接调试场景。

### 2. `frontend/src/api/http.js`

**修改前**: `VITE_API_BASE` (未设置，默认 `http://localhost:8080`)
**修改后**: `VITE_API_BASE_URL` (与 `http.ts` 统一，默认 `/api`)

**说明**: 修复了前端两个 HTTP 客户端使用不同环境变量名的问题。生产环境下使用相对路径 `/api`，由 Nginx 代理到后端，避免硬编码服务器地址。

## 七、与本地开发环境的区别

| 方面 | 开发环境 | 生产环境 |
|------|----------|----------|
| 启动方式 | 分别启动前端 `npm run dev` + 后端 `mvn spring-boot:run` | 一键 `bash deploy.sh` |

## 八、部署问题排查记录

实际部署到阿里云 ECS 过程中遇到的 4 个问题及修复方案。

### Bug #1：Docker Hub 镜像拉取超时

**现象**：`docker compose build` 时报 `dial tcp ... i/o timeout`

**根因**：国内服务器无法直接访问 Docker Hub（registry-1.docker.io）

**修复**：配置阿里云 Docker 镜像加速器
```bash
sudo tee /etc/docker/daemon.json <<-'EOF'
{
  "registry-mirrors": [
    "https://registry.cn-hangzhou.aliyuncs.com",
    "https://docker.1ms.run",
    "https://docker.xuanyuan.me"
  ]
}
EOF
sudo systemctl daemon-reload && sudo systemctl restart docker
```

### Bug #2：注册后前端显示"未认证或凭证失效"

**现象**：注册页面点击注册后出现 `UNAUTHORIZED(401)`

**根因**：`http.js` 中 `VITE_API_BASE_URL=/api` 与 API 路径 `/api/v1/auth/register` 拼接成 `/api/api/v1/auth/register`，导致请求未命中 JWT 拦截器的排除路径 `/api/v1/auth/**`，被拦截返回 401

**修复**：
- `http.js`：默认值从 `/api` 改为 `''`（空字符串）
- `.env.production`：`VITE_API_BASE_URL` 设为空值

**原理**：API 调用路径本身已包含 `/api/v1/...` 前缀，不需要再叠加。Nginx 通过 `location /api/` 代理到后端，浏览器中 `fetch('/api/v1/auth/register')` 作为相对 URL 由 Nginx 正确转发。

### Bug #3：JWT Secret 格式不合法导致后端无法启动

**现象**：后端容器反复重启，日志显示 `Illegal base64 character: '-'`

**根因**：`docker-compose-prod.yml` 中 JWT Secret 的默认值 `change-me-in-production` 包含连字符 `-`，不符合 jjwt 库对 Base64 编码的要求。由于 `deploy.sh` 脚本上传方式走的是非 git 路径，`export CAMPUSHUB_JWT_SECRET` 未被执行或未正确传入容器。

**修复**：重新生成合法密钥并重启后端容器
```bash
export CAMPUSHUB_JWT_SECRET="$(openssl rand -base64 32)"

docker compose -f docker-compose-prod.yml stop backend
docker compose -f docker-compose-prod.yml rm -f backend
docker compose -f docker-compose-prod.yml up -d backend
```

**后续改进**：修改 `application-prod.yml` 中的 JWT 默认值为不含特殊字符的合法 Base64 字符串，或程序层面在启动时检查密钥合法性。

### Bug #4：502 Bad Gateway（Nginx 连不上后端）

**现象**：`curl localhost/api/v1/health` 返回 502 Bad Gateway

**根因**：Bug #3 导致后端容器崩溃且未恢复，Nginx 无法连接到 upstream

**修复**：修复 Bug #3 后后端正常启动，Nginx 自动恢复代理。
